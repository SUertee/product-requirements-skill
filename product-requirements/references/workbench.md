# 工作台页面规范

生成内部工作台时读取本文件和 [内置 UI 规范](ui-design.md)。页面使用 `../assets/workbench-template.html`、`../assets/workbench.css` 和 `../assets/workbench.js`，由 `../scripts/build_documents.py` 将项目数据与真实文件清单注入 HTML。

## 资源位置

| 内容 | 位置 | 用法 |
| --- | --- | --- |
| 页面任务、字段、关联与状态 | references/workbench.md | 生成和修改工作台时读取 |
| 视觉规则与组件约定 | references/ui-design.md | 决定布局、样式和交互状态 |
| 可复用 HTML、CSS、JS | assets/workbench-*、assets/workbench.js | 直接参与输出生成 |
| ParTrace Vision 原工作台 | 仓库 docs/references/partrace-workbench/ | 开发时比较与调整，随仓库保留 |
| 当前客户的工作台 | 每次运行的输出目录 workbench/index.html | 随同版本文档和素材交付 |

安装 Skill 包后，页面生成依赖包内规范和 assets。ParTrace 原页面含原项目数据和媒体，通用模板使用当前项目数据填充。

## 内容关联

来源片段以 source_id 标识，需求以 requirement_id 标识。业务模块关联需求，方案、PRD、页面、数据实体和接口回查关联需求。会议通过 material_ids 关联素材，素材通过 source_ids 关联逐字稿。各页面读取同一版本的 project.json 和 manifest.json。

客户项目的业务模块放在“功能需求”。Skill 自身的输入、理解、建模、文档、原型、图示、汇总、评审八个处理模块在开发架构文档维护。

## 页面框架

沿用 ParTrace Vision workbench 的深色侧栏、浅色内容区、模块选择与详情、嵌入预览和独立打开模式。七个一级名称固定为总览、会议素材、功能需求、方案文档、原型预览、技术设计、评审记录。

顶栏显示项目标识、当前页面与导出数据入口。页面标题下保留真实版本、评审状态和待确认数量。搜索与筛选放在适用页面。卡片直接展示实际内容，规则、依据和修订通过明确的按钮切换显示。

### 总览

- 首屏显示项目名称、目标、面向角色、范围与已有核心流程。版本与草稿状态由页面标题区展示。
- 成果区域提供方案文档、原型和技术设计入口，根据真实文件清单显示可用状态。
- 显示最多三项关键疑问，优先使用需求中的 open_questions；缺少显式疑问时显示结构检查问题。点击后进入对应需求或评审。
- 需求画像完整内容在方案文档按章节阅读，缺失项显示待确认。

### 会议素材

- 默认显示素材库，顶部按钮切换素材、导入和处理记录。已提供有来源的会议重点时，先显示重点，通过时间入口定位完整逐字稿。
- 桌面左侧素材列表，右侧展示选中素材。窄屏列表转为横向选择。
- 列表名称下显示素材类型与原话数量。会议名、日期随所选素材显示。
- 右侧显示会议日期、时长、原件下载和有效的飞书妙记入口。会议重点与逐字稿通过按钮切换；原话每页最多 30 段，跨页来源回查自动定位。原话显示时间与说话人，source_id 保存在数据中。已有录音随逐字稿展示播放器。
- 原话下提供关联 REQ，点击进入对应业务模块。需求点击来源后回到素材并突出对应片段。
- 前情资料作为单独列表项，展示客户背景、历史项目和已有基线中的实际内容。
- 当前文件未附带、尚无逐字稿和搜索无结果分别表达。本地运行器提供文件导入、指定妙记获取、接收箱与失败重试。ASR、设备同步和自动分析任务状态随真实能力接入。

### 功能需求

- 提供“模块图”和“需求列表”两个视图，保留当前搜索、筛选与选中模块。已有实际模块图时默认进入图视图，缺少图示时先展示列表。
- 全局搜索、需求确认状态和证据类型可组合筛选。尚未关联模块的需求进入“待归类”。
- 模块图或需求表占据主区，模块选择条位于下方。选中模块后，在宽版详情中左侧选择需求、右侧阅读当前一条需求；关联页面、数据、接口和交接在“相关内容”中查看。
- 模块图使用实际生成的 Archify diagrams/modules.html，节点选择联动同一模块的需求详情。关系只采用 project.module_relations 的已有定义，缺失时显示待补充。
- 需求名称作为主标题，列表以名称和状态识别对象。编号以“需求编号 REQ-007”等辅助信息呈现，内部稳定标识用于引用和修订。默认显示功能、验收与具体疑问。
- 功能、规则、会议原话、修改通过页内按钮切换。角色、触发、输入、输出和异常在规则中完整查看，来源可回查原话，修改沿用字段锁定与评审流程。
- 确认状态与证据类型各自表达。页面浏览保留已有人工锁定数据，修改通过 Skill 生成下一版本。

### 方案文档

- 顶部切换项目方案和 PRD，左侧选择章节，右侧显示当前章节和完整文件入口。功能需求、原始依据等多条内容进一步点选单条阅读。
- 项目方案包含摘要、背景、目标范围、解决方案、实施资源、验收风险与文档信息。PRD 沿用 assets/prd-template.md，覆盖范围、角色、模型、功能、交互、约束、验收和来源。
- 正文使用标题、段落和列表，真实生成章节与模板保持一致。需要定位的 REQ ID 和来源保留在文档内。
- 生成草稿与人工确认各自标注，以实际文档和评审数据为准。

### 原型预览

- 默认预览已生成的交互页面，顶部选择页面与设备尺寸，提供独立打开入口。页面定义与生成操作通过页内按钮进入。
- 产品类型和目标设备决定预览尺寸，页面任务关联 REQ，展示实际版本。
- 页面清单、核心任务和模拟能力说明随真实产物接入。接口模拟和真实接口状态随实际产物标明。页面定义列表可从当前 project.pages 展示，并回查关联 REQ。
- 原型尚未生成时显示待生成及所需的定义确认，保留其他成果入口。
- 客户分享范围由负责人选择并复核，内部工作台与资料按授权发布。

### 技术设计

页内使用流程架构、数据库、API 三个标签。

| 标签 | 内容 | 关联 |
| --- | --- | --- |
| 流程架构 | 业务流程、包含输入层／理解层／生成层的技术架构、独立图示入口 | 当前流程、需求、项目版本 |
| 数据库 | 实体、字段、类型、关系，已生成的 Schema Canvas 页面 | 业务模型及需求 |
| API | 名称、方法、路径、请求、响应、异常、确认状态 | 接口 ID、模块和 REQ |

技术页面通过设计／生成按钮进入对应内容。数据库优先显示实际生成的 Schema Canvas，字段详情由图内选择打开。缺少 ERD 时展示已有实体定义。图示与 ERD 按真实文件清单嵌入。模型中的未知字段保留待确认，接口草案与实际接通状态分别记录。键盘可切换标签，长表格在自身容器滚动。

### 评审记录

- 显示当前版本、原基线和文档评审状态。
- 问题按对象显示具体原因与缺失字段，支持搜索。
- 评审决定展示已有决定，未记录时保留空态。本地运行器可保存对象、结论、意见与选填记录人，绑定项目版本，以 revision 检查较新的记录；提供 JSON 导出供 Skill 修订。
- 定义确认覆盖范围、规则和验收，最终复核覆盖原型行为和客户可见内容。
- 差异、影响范围与发布记录随版本能力接入。静态工作台提供浏览，本地运行器持久化评审意见，主 Skill 处理反馈、修订与新版本生成。

## 内容与状态检查

- 能从 REQ 回到原话，从原话进入对应 REQ，筛选结果保留实际匹配项。
- 缺少材料、模块、模型或产物时仍可浏览其他页面，提供具体缺失信息。
- 所有文件入口对应实际输出文件，模拟数据标明来源；原项目客户数据留在原始参考中。
- 评审决定、生成状态和真实测试结论分别记录，使用人工决定更新文档和原型版本。
- 桌面与窄屏检查选中态、中文长标题、表格滚动、键盘焦点和音频控件。
