# 内置 UI 规范 v1.0

生成内部工作台和客户原型时使用。样式变量与通用组件在 ../assets/ui.css，工作台页面约定见 [工作台页面规范](ui-design.md)，原型页面约定见 [原型设计与生成](prototype.md)。

## 原则 · 简洁清晰

工作台给 PM／FDE 推进项目，也给首次接触项目的人看懂：项目在做什么、各页有什么、产出了什么、下一步做什么。

- **内容克制**：只放当前任务需要的结论、内容和操作。删掉复述标题的说明，长内容给查看入口。
- **层级清楚**：每页一个主要任务，用字号、间距和少量分组区分主次。
- **交互直接**：入口名就是内容或动作，选中对象后在旁边显示详情。
- **必要信息完整**：来源、待确认项、错误原因和处理结果始终可见或一步可达。

每增加一个元素，先问它帮用户理解、判断还是完成什么；说不出来就不加。

## 样式变量

所有颜色、字号、圆角都用 ui.css 开头的 `--ui-*` 变量，不在其他地方写具体数值。`tests/test_ui_tokens.py` 会检查。客户有品牌规范时，只在项目级覆盖这些变量，覆盖后重新检查对比度。

| 类别 | 变量 | 用途 |
| --- | --- | --- |
| 底色 | `page` `surface` `surface-subtle` `surface-muted` | 页面、内容卡、引用与表头、选中与标签底 |
| 文字 | `ink` `ink-2` `muted` `on-accent` | 标题与正文、次要正文、辅助说明、主色上的文字 |
| 线条 | `border` `border-strong` | 卡片与分隔线、输入框与按钮边框 |
| 主色 | `accent` `accent-ink` `accent-soft` `accent-soft-strong` `accent-border` | 主操作、链接与选中文字、选中底色、悬停、选中边框 |
| 导航 | `nav` `nav-ink` `nav-muted` `nav-hover` `nav-active` `nav-line` | 深色侧栏 |
| 状态 | `success` `warning` `danger`，各配 `-soft` 底色；`success-mark` `warning-mark` | 状态文字、浅底标签、圆点与勾选 |
| 字号 | `text-xs` 12、`text-sm` 13、`text-md` 15、`text-lg` 18、`text-xl` 24 | 标签与编号、辅助说明、正文、区块标题、页面标题 |
| 圆角 | `radius-sm` 8、`radius` 10、`radius-pill` | 按钮与输入框、卡片与面板、胶囊标签 |
| 阴影 | `shadow-overlay` `backdrop` | 只用于弹层 |

间距使用 4、8、12、16、24、32、48px。正文行高 1.6，长文阅读区 1.8。字体为 Inter，中文回退 PingFang SC、Microsoft YaHei。

## 组件与状态

| 组件 | 要求 |
| --- | --- |
| 按钮 | 主操作用实底，次要操作用描边，轻量操作用透明底，删除使用危险色。图标与文字并排。桌面使用常规和紧凑两档，窄屏操作按钮触控高度至少 44px。提供悬停、键盘焦点、禁用和提交中状态，提交中阻止重复请求 |
| 输入项 | 持久标签、必要提示、就近错误，提交失败保留已填内容。用原生控件 |
| 卡片 | 标题 + 真实内容 + 状态 + 操作，不写介绍性描述 |
| 表格 | 在自身容器内横向滚动，表头用 `surface-subtle` |
| 状态标签 | 文字加颜色，不只靠颜色表达 |
| 页内切换 | 标签页使用主色下划线，分段按钮选中用 `accent-soft` 底与 `accent-ink` 字 |
| 页面状态 | 加载中、空数据、无筛选结果、出错可重试、无权限。空态写清缺少什么；示例数据要标明 |
| 弹层 | 焦点进入，Escape 关闭，关闭后焦点回到触发处 |

## 页面模式

| 场景 | 结构 |
| --- | --- |
| 内部工作台 | 192px 深色侧栏 + 内容区（最大 1320px），七页：总览、会议素材、功能需求、方案文档、原型预览、技术设计、评审记录 |
| 列表与详情 | 左侧选择、右侧阅读一条；窄屏改为上下排列 |
| 内部业务系统原型 | 侧栏、标题与操作区、筛选、列表、详情 |
| 审批与操作流程 | 步骤、当前任务、表单、校验、确认与结果 |
| 数据分析工具 | 指标口径、筛选、图表、明细与数据来源 |
| 移动端服务 | 底部导航、核心任务、单列表单、操作结果 |

产品类型、目标设备、已有样式来源和设计决定写入 project.json 的 `design_context`。图示节点、栏目和按钮使用具体业务名称。

## 检查清单

- 桌面与 390px 宽度：无横向滚动条，中文换行正常，长字段不撑破布局，导航可用。
- 窄于 900px：侧栏收为横向导航，表单与卡片单列，触控目标至少 44px。
- 键盘能走完主流程，焦点可见。
- 普通文字对比度至少 4.5:1，大字至少 3:1。
- 记录实际浏览器检查结果与未通过项。

## 工作台页面规范

生成内部工作台时读取本文件和 [内置 UI 规范](ui-design.md)。页面使用 `../assets/workbench-template.html`、`../assets/workbench.css` 和 `../assets/workbench.js`，由 `../scripts/build_documents.py` 将项目数据与真实文件清单注入 HTML。

### 资源位置

| 内容 | 位置 | 用法 |
| --- | --- | --- |
| 页面任务、字段、关联与状态 | references/ui-design.md | 生成和修改工作台时读取 |
| 视觉规则与组件约定 | references/ui-design.md | 决定布局、样式和交互状态 |
| 可复用 HTML、CSS、JS | assets/workbench-*、assets/workbench.js | 直接参与输出生成 |
| ParTrace Vision 原工作台 | 仓库 docs/references/partrace-workbench/ | 开发时比较与调整，随仓库保留 |
| 当前客户的工作台 | 每次运行的输出目录 workbench/index.html | 随同版本文档和素材交付 |

安装 Skill 包后，页面生成依赖包内规范和 assets。ParTrace 原页面含原项目数据和媒体，通用模板使用当前项目数据填充。

### 内容关联

来源片段以 source_id 标识，需求以 requirement_id 标识。业务模块关联需求，方案、PRD、页面、数据实体和接口回查关联需求。会议通过 material_ids 关联素材，素材通过 source_ids 关联逐字稿。各页面读取同一版本的 project.json 和 manifest.json。

客户项目的业务模块放在“功能需求”。Skill 自身的输入、理解、建模、文档、原型、图示、汇总、评审八个处理模块在开发架构文档维护。

### 页面框架

深色导航、浅色阅读区，冷灰分隔线，蓝色用于选中和定位。保留模块选择、详情、嵌入预览和独立打开。七个一级名称固定为总览、会议素材、功能需求、方案文档、原型预览、技术设计、评审记录。

侧栏顶部显示简短项目名和搜索入口，七个导航项带图标；桌面宽度可收起为仅图标，收起状态保存在浏览器本地。搜索入口打开全局搜索，覆盖页面、需求和会议原话，结果直接跳转到对应位置。内容区只保留页面标题，不设面包屑和导出数据入口。页面标题直接进入当前内容，不附加草稿、版本和待确认总数。版本和评审信息在评审记录及具体对象中查看。搜索与筛选放在适用页面。卡片直接展示实际内容，规则、依据和修订通过明确的按钮切换显示。

#### 总览

- 首屏用项目名称与一句话说明项目用途，优先读取 project.summary，缺省使用 desired_outcomes；面向角色与范围以标签展示，采用实际项目数据。业务流程在方案文档中阅读，总览不重复展示。
- 项目卡片下方用四个数字说明现状：当前版本及其生成日期、已迭代版本数、会议次数及最近一次日期、当前进度及已确认需求数。生成日期来自页面数据的 generated_at，缺少时只显示版本号；迭代数取自版本号。
- “成果”逐项列出会议素材、功能需求、方案文档、原型预览、技术设计和评审记录的实际状态，每项可进入对应页面；缺少成果显示暂无，评审记录显示待确认问题数。成果与待确认事项并列，窄屏依次显示。最近会议可打开素材，已登记的业务流程提供流程图入口。
- 显示最多三项关键疑问，优先使用需求中的 open_questions；缺少显式疑问时显示结构检查问题。点击后进入对应需求或评审。
- 需求画像完整内容在方案文档按章节阅读，缺失项显示待确认。

#### 会议素材

- 默认进入素材库，顶部切换素材、导入和处理流程。素材选择、日期、时长和原件操作放在同一工具区。
- 有会议重点时，使用状态、结论和时间码三列。点击时间码保留当前结论列表，在原话面板联动高亮并显示前后一段上下文；关闭或按 Esc 返回时间码。窄屏将原话放在列表下方。
- 支持切到完整逐字稿，每页最多 30 段。进入完整稿时定位到选中片段所在页；搜索仅查当前素材。原话显示时间与说话人，已有录音时可用时间码定位播放器。
- 原话下关联需求可回到对应需求详情；需求中的证据入口也可回到对应材料和原话。没有会议重点时直接打开逐字稿。
- 前情资料作为单独素材选项，展示客户背景、历史项目和已有基线中的实际内容。
- 素材用于阅读会议重点、原话与需求依据；导入负责文件和妙记接收；处理流程按素材展示接收、转写、需求分析、工作台四个阶段，状态读取实际任务，失败显示原因，分析任务只保留最近三条，隐藏内部任务编号。
- 当前文件未附带、尚无逐字稿和搜索无结果分别表达。本地运行器提供文件导入、指定妙记获取、接收箱与失败重试。ASR、设备同步和自动分析任务状态随真实能力接入。

#### 功能需求

- 提供功能模块、用例图、需求列表三个视图，保留搜索、筛选与选中模块。功能模块回答有哪些业务功能，用例图回答谁使用哪些功能，需求详情用于敲定行为、范围、规则和验收。默认进入需求列表，功能模块和用例图作为第二、第三视图。
- 全局搜索、需求确认状态和证据类型可组合筛选。尚未关联模块的需求进入“待归类”。
- 需求列表左侧按模块分组列出需求，右侧一屏阅读当前一条：依据类型与确认状态、功能内容、验收标准、需要确认、业务规则和会议原话依次展示，不再分页签。修改入口在本机工作台中以按钮切换。
- 业务模块与用例图视图中，图占据主区，点选节点后在下方宽版详情中左侧选择需求、右侧阅读；关联页面、数据、接口和交接在“相关内容”中查看。模块选择条仅在模块图缺失时出现。
- 用例图从当前需求的 role 与 title 建立角色、功能和关联，系统边界包围功能，角色位于边界外。暂缓与取消需求不进入用例图；角色不明时不补造角色或权限。点击功能进入对应需求，支持键盘选择。点击和键盘焦点使用椭圆轮廓高亮，移除 SVG 分组默认的矩形焦点框。
- 功能模块图使用实际生成的 Archify diagrams/modules.html，节点选择联动同一模块的需求详情。关系只采用 project.module_relations 的已有定义，缺失时显示待补充。
- 需求名称作为详情主标题。左栏按业务模块分组，同一行展示名称和状态，选中行用蓝色定位。编号以“需求编号 REQ-007”等辅助信息呈现，内部稳定标识用于引用和修订。默认显示功能、验收与具体疑问。
- 功能、规则、会议原话、修改通过页内按钮切换。角色、触发、输入、输出和异常在规则中完整查看，来源可回查原话，修改沿用字段锁定与评审流程。
- 确认状态与证据类型各自表达。页面浏览保留已有人工锁定数据，修改通过 Skill 生成下一版本。

业务规则使用字段行，异常处理和会议原话分别呈现。结构标题使用深色标记，关联和定位使用蓝色，须确认的区块使用琥珀色。图标用作文字之外的识别线索。

#### 交给开发与排期

- 开发提示词不在方案文档中。总览“成果”最后一项为“交给开发”：至少一条需求已确认时可展开预览、复制全文或下载；否则显示“确认需求后可生成”。
- 方案文档（项目方案、PRD）从上到下连续阅读，左侧章节列表随滚动高亮，点击跳到对应章节；编辑、打印、下载和保存在阅读区顶部。
- 各页搜索统一为页面标题右侧的放大镜，点击或输入时展开，筛选按钮紧挨其后。
- 方案文档中的来源编号显示为文内引用 [n]，悬停显示时间与原话，点击跳到会议原话；“原始依据”一章为按编号排列的引用列表。
- 评审在对应页面完成：需求详情底部填写意见并选择“确认／需要修改／暂缓”，或“修改内容”；有待生效的结论或修改时，功能需求页顶部显示“生成新版本”。评审记录页只保留“评审记录 · 交付”（客户复核仅在开启问卷服务时出现），记录列表顶部是“版本记录”：从新到旧列出每个版本怎么来的（分析会议／评审生效／生成成果／修改文档）、基于哪一版、带来的结论（逐条列出）、内容变化数和成果（沿用上一版的标“沿用 vX”），其下是本版相对上一版的变化和本版已记录的结论。
- 数据模型与技术架构一致：上方为实体卡片，点选后下方显示字段表（字段、类型、说明）。
- 会议素材只有“素材 · 导入”。导入后的每份素材一行：名称、类型、段数、状态和一个操作（生成新版本、重试、转写或查看原话）；等待宿主分析的任务在同一列表中，可开始分析或上传结果。
- 需求详情的会议原话默认显示前 2 条、每条最多两行，其余按需展开。
- 会议素材“导入”先选来源（本地文件或飞书妙记），再选文件或粘贴链接，点“导入”；“最近导入”每条只显示名称、类型、段数、状态和直接操作，内部文件折叠。只有一份会议时直接显示会议名，不出现下拉框；会议重点没有状态时不显示状态列。下拉框统一边框、高度和箭头。“处理流程”每份素材一行状态，主操作为“生成新版本”，版本号自动递增。会议重点与原话面板之间可拖动或用方向键调整宽度。

#### 方案文档

- 顶部切换项目方案和 PRD，左侧选择章节，右侧显示当前章节与编辑、打印、下载入口。功能需求、原始依据等多条内容进一步点选单条阅读。
- 项目方案按 assets/document-templates.md 生成，包含摘要、背景、目标范围、解决方案、实施资源、验收风险与文档信息。PRD 按 assets/document-templates.md 生成，覆盖范围、角色、模型、功能、交互、约束、验收和来源。
- 正文使用标题、段落和列表，真实生成章节与模板保持一致。需要定位的 REQ ID 和来源保留在文档内。
- 章节正文可编辑并预览，本地服务通过“保存新版本”持久化，旧版保留。保存校验文档基线哈希，冲突时保留当前页面草稿并提示错误；未保存内容只在当前页面内存中。
- 人工正文保存在 document_overrides，后续自动分析保留并记录冲突。正文修改不直接更改结构化需求，需求字段仍通过功能需求页修订。
- “打印 / PDF”打印整份当前正文（含未保存修改），在浏览器打印窗口选择另存为 PDF；“下载正文”输出 Markdown。静态分享页可编辑预览与下载，持久保存需要本地服务。
- 生成草稿与人工确认各自标注，以实际文档和评审数据为准。

#### 原型预览

- 尚无原型时显示生成前必须完成的三项：确认功能需求、补全验收标准、确认非功能需求。每项显示实际进度，“去处理”直接打开功能需求页中第一条待处理的条目；缺验收标准或还没有非功能需求时改为“复制起草指令／复制整理指令”，交给 Skill 起草后回到需求下核对。已评审但还没生成新版本的结论计入进度并标“待生效”，页面顶部提示先在功能需求页生成新版本。页面本身不生成原型（设计需要宿主里的 Skill），下方“交给 Skill 生成原型”给出可复制的指令；有缺项时指令会写明缺什么，要求 Skill 先补齐再生成。
- 已有设计原型时，左侧列出原型页面，中间预览，右侧显示当前页的目的、关联功能需求、非功能需求及体现方式、页面状态和可见角色，整体体现的 NFR 单独列出。原型内跳转时右侧同步切换，只接受当前预览窗口的消息。
- 顶部一行显示版本和覆盖情况，按目标设备提供尺寸切换，“标注需求”在原型上高亮 data-req／data-nfr 元素，提供独立打开。排除的需求和不适用的 NFR 列在“不在原型中”。
- 只有 pages 字段／操作定义的旧原型沿用页面按钮与尺寸切换。
- 客户分享范围由负责人选择并复核，内部工作台与资料按授权发布。

#### 技术设计

页内使用技术架构、数据模型、接口三个标签。

| 标签 | 内容 | 关联 |
| --- | --- | --- |
| 技术架构 | 系统层次、组件、运行位置和组件连接；由 technical_architecture 提供 | 技术设计、关联需求和来源 |
| 数据库 | 实体、字段、类型、关系，已生成的 Schema Canvas 页面 | 业务模型及需求 |
| API | 名称、方法、路径、请求、响应、异常、确认状态 | 接口 ID、模块和 REQ |

技术页面直接展示技术架构、数据模型和接口，不设置设计／生成模式。数据库优先显示实际生成的 Schema Canvas，字段详情由图内选择打开。缺少 Schema Canvas 成果时，按当前实体和相邻关系提供可点选关系图和字段明细。技术架构采用独立结构化数据，优先嵌入 Archify architecture 产物并贴合内容高度；没有产物时使用基础 SVG。不复用业务流程图或功能模块图。缺少数据时显示技术架构待确认。技术架构卡片提供图题与独立打开入口，嵌入视图隐藏重复的图例和工具栏。业务流程仍保留在总览与方案，模块图留在功能需求。ERD 按真实文件清单嵌入，嵌入页通过来源窗口校验的高度消息贴合实际内容，实体详情变化后重新计算；高度设有边界。模型中的未知字段保留待确认，接口草案与实际接通状态分别记录。键盘可切换标签，长表格在自身容器滚动。

#### 评审记录

- 使用待确认、已记录、版本变更、交付四个页内入口，默认进入待确认。
- REQ ID 用于内部关联，评审列表与对象选择使用业务名称，列表显示每项的具体问题数。
- 待确认按业务需求名称选择，右侧合并同一需求的问题与处理意见。重复原因去重，只列出有具体问题的对象，以及从需求详情进入评审的那一条；支持搜索和返回需求／原话。
- 保存意见绑定当前所选需求，阶段由所在页面确定；历史意见在已记录中查看，版本号和变更在版本变更中查看，发布复核与客户包在交付中处理。
- 评审决定展示已有决定，未记录时保留空态。本地运行器可保存对象、结论、意见与选填记录人，绑定项目版本，以 revision 检查较新的记录；提供 JSON 导出供 Skill 修订。
- 定义确认覆盖范围、规则和验收，最终复核覆盖原型行为和客户可见内容。
- 差异、影响范围与发布记录随版本能力接入。静态工作台提供浏览，本地运行器持久化评审意见，主 Skill 处理反馈、修订与新版本生成。

### 内容与状态检查

- 能从 REQ 回到原话，从原话进入对应 REQ，筛选结果保留实际匹配项。
- 缺少材料、模块、模型或产物时仍可浏览其他页面，提供具体缺失信息。
- 所有文件入口对应实际输出文件，模拟数据标明来源；原项目客户数据留在原始参考中。
- 评审决定、生成状态和真实测试结论分别记录，使用人工决定更新文档和原型版本。
- 桌面与窄屏检查选中态、中文长标题、表格滚动、键盘焦点和音频控件。

技术架构图节点可选择，下方组件切换条与详情同步。详情展示职责、开发内容、交付标准和关联需求；与业务功能模块的需求核对保持区分。嵌入图通过受控消息传递组件标识，父页面只接受当前架构窗口及有效组件索引，选中态回传图内；鼠标、Enter 和空格均可选择。缺少开发说明或标准时显示待补充。


#### 会议中的客户复核

可选功能，主流程不依赖它。客户反馈的主要途径是体验发布后的原型，负责人把反馈作为素材导入后修订；需要在会议现场逐题确认疑问时再使用问卷。

- 在「评审记录 → 负责人复核」保存自己的决定。正式应用意见后生成新版本。
- 在「评审记录 → 客户复核」选择关联需求并核对题目、候选项，然后生成答题链接。客户可点选、补充、自填或暂缓，提交后在同页刷新查看。客户页面只显示选定题目和版本，收到的回答进入会议素材接收箱，供后续分析。
- 启动本地工作台时增加 `--customer-host 192.168.1.10 --customer-port 8766`，IP 换成负责人电脑可被客户访问的局域网地址。客户访问单独的问卷端口，负责人仍通过本机地址进入工作台。双方需要能访问该地址，远程会议仍需要另行安排可达网络。
