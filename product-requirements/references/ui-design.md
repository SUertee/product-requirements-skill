# 内置 UI 规范 v0.3

本规范供主 Skill 生成客户原型和内部工作台时使用，基础样式位于 ../assets/ui.css。视觉参考 ParTrace Vision 的 workbench 工作台中的侧栏、内容区和预览结构，具体页面围绕当前客户的任务与数据组织。

工作台页面与内容约定见 [工作台页面规范](workbench.md)。包内 assets/workbench-template.html、workbench.css 和 workbench.js 参与实际生成。ParTrace Vision 的原工作台副本在仓库 docs/references/partrace-workbench/ 保留，供开发时比对。

## 第一原则 · 简洁清晰

设计理念是克制。工作台用于 PM／FDE 回看、推进项目，以及向首次接触项目的人分享和沟通。首次阅读者应能看懂项目在做什么、各页有什么、目前产出了什么，以及下一步可以做什么。

- **内容克制**。优先展示当前任务需要的结论、内容和操作，移除重复标题、说明和数据。完整文档、原话与技术细节保留清楚的查看入口。
- **层级清晰**。每页围绕一个主要任务组织，主内容与辅助信息容易区分。通过排版、间距和少量分组建立层次。
- **交互直接**。入口名称表达内容或动作，选择对象后展示对应详情，减少寻找和多层切换。
- **视觉克制**。统一圆角、颜色、字号与组件。强调色、边框和动效用于表达选中、关联或状态，装饰随阅读需要取舍。
- **内容与功能直接表达**。用实际板块、可视化内容和操作呈现功能，按下文的表达规则检查。
- **必要信息完整**。来源、待确认项、错误和处理结果保持可见或可直接查看。正文保持可读字号，长内容按任务分层阅读。

每次增加或保留一个元素，都核对它帮助用户理解什么、判断什么或完成什么。评审同时检查内容能否精简、入口是否清楚、信息能否回查。

## 确认设计依据

读取已确认 PRD、页面任务、用户角色与目标设备。核对客户已有品牌、设计系统与历史页面，记录适用的样式来源。需要类似产品参考时记录具体交互模式及出处。将 product_type、target_devices、existing_style_sources、reference_products、design_system_version 和 design_decisions 存入 project.json 的 design_context。

使用本规范作为默认设计系统，客户明确的样式约束作为项目级变量覆盖。覆盖后重新检查可读性和组件状态。已有数据中的 selected_ui_skills 保留为历史生成信息，新版本记录内置规范版本。

## 视觉与布局

- 字体默认 Inter，中文使用 PingFang SC、Microsoft YaHei 和系统无衬线回退。正文 15px，行高 1.6，辅助文字 13px，页面标题 25px。
- 浅灰蓝页面、白色内容卡、深色侧栏、蓝色主操作，成功、待确认和错误采用各自语义色。颜色同时配文字或图标反馈。
- 间距使用 4、8、12、16、24、32、48px。正文内容按任务分组，卡片圆角 10px，边框清晰。每个操作区突出一个主要动作。
- 桌面工作台采用 228px 侧栏与弹性内容区，内容默认最大宽度 1500px。生成的 ERD、架构图和原型通过独立页面入口或预览区打开。
- 窄于 900px 时收起侧栏为可访问导航。表格在自身容器内横向滚动，表单和内容卡改为单列，触控目标至少 44px。

## 按产品类型组织

| 产品类型 | 页面结构 |
| --- | --- |
| 内部业务系统 | 侧栏、页面标题与操作区、筛选、列表、详情 |
| 审批与操作流程 | 步骤、当前任务、表单、校验、确认与结果 |
| 数据分析工具 | 指标口径、筛选、图表、明细与数据来源 |
| 移动端服务 | 移动导航、核心任务、单列表单与操作结果 |
| 客户展示原型 | 围绕已确认主流程组织入口、关键操作与结果反馈 |

内部工作台采用总览、会议素材、功能需求、方案文档、原型预览、技术设计、评审记录七页。技术设计使用技术架构、数据模型和接口标签。功能模块和角色用例属于功能需求，业务流程属于总览和方案；不把业务流程冒充技术架构。首屏呈现目标、范围、成果入口与待确认问题。会议素材、功能需求和方案文档采用列表选择与详情布局，完整约定见工作台页面规范。

## 卡片内容与文案

卡片以标题、真实内容、状态和可执行操作组织信息。功能卡片下方和 footer 中的介绍性 description 移除。必要的字段标签、错误原因、输入约束和状态反馈就近显示。

- 功能入口直接使用功能名称与操作，列表卡展示实际记录，成果卡提供文件、版本或预览，评审卡展示具体问题与确认操作。
- 标题已表达含义时，移除重复解释。表格、字段、图示或操作已能说明功能时直接呈现内容。
- 保留必要的错误原因、输入约束、待确认状态、示例数据提示和来源信息。较长业务背景放到按需展开的详情中。
- 生成后检查每段辅助说明是否增加独立信息，删除只复述标题或操作的句子。

## 用板块与可视化表达

- 模块关系用可点击的模块图，业务过程用流程图或时序图，数据结构用实体关系图，操作效果用可交互原型呈现。
- 实际材料、需求、文档和待确认事项使用可点选的列表与正文。选择对象后显示对应内容，相关原话和成果提供直接入口。
- 图示节点、栏目和按钮使用具体业务名称。必要的专业术语搭配易懂的业务名称，来源定位显示可理解的时间或段落。
- 总览通过项目目标、已有主流程、成果状态和下一步操作建立上下文。下一步入口依据实际材料、需求复核与成果状态决定。
- 分享给首次接触项目的人时，项目名称、目标和页面标题应能独立表达内容，来源和状态可回查。页面主内容承担解释任务。

评审时让首次接触项目的人指出项目目标、当前页面的主要内容、已有成果和可执行的下一步，核对其理解是否符合项目事实。

## 组件与行为

- 按钮区分主操作、次操作和危险操作，包含默认、悬停、键盘聚焦、禁用和提交中状态。提交中阻止重复请求并展示结果。
- 输入项提供持久标签、必要提示和就近错误，提交后保留用户输入。使用原生控件和语义化 HTML。
- 列表与表格包含加载、空数据、无筛选结果、失败与重试状态。使用模拟数据时显示“示例数据”。
- 详情与弹层支持键盘操作、Escape 关闭、焦点进入和关闭后恢复。确认行为显示关联版本与范围。
- 原型任务关联 REQ ID，页面主流程、返回和关键异常可操作。实际生成能力与示例接口状态保持一致。
- 内部资料、图示与客户原型使用独立入口，发布包包含用户选定内容。

## 验证

在桌面与 390px 宽度检查布局，确认中文换行、缩放、长字段、局部表格滚动及导航可用。键盘遍历主流程，检查可见焦点、弹层和表单错误反馈。普通文本对比度至少 4.5:1，大文本至少 3:1。记录实际浏览器检查结果和未通过项。


## 当前工作台生成资产

assets/workbench-template.html 定义七页的应用外壳，assets/workbench.css 复用 ParTrace Vision workbench 的样式基础，assets/workbench.js 组织项目数据与页面交互。侧栏名称使用总览、会议素材、功能需求、方案文档、原型预览、技术设计、评审记录。


## 工作台视觉收敛

v0.2 统一使用单套工作台样式。深蓝灰侧栏、浅灰页面与白色内容区承载七个简短入口。内容区按 20px 节奏分组，常规卡片 24px 内边距，层级通过字号、间距和边框表达。

总览优先展示目标、范围和具体疑问，需求数量使用紧凑统计行，八要素画像在文档中按章节阅读。模块内的需求采用分隔线组织，减少嵌套卡片边框。文档以正文层级阅读，实体字段使用表格，结构化内容使用列表与定义项。

辅助文案只提供独立信息。运行／评审状态使用文字，页面空态说明具体缺失内容。移动端导航横向排列，表格局部滚动。


## 功能需求样板 v0.3

功能需求使用紧凑工具栏、模块选择条、主内容区和按选择更新的详情区。桌面并排展示，窄屏改为纵向阅读。模块图与列表共用筛选和选中状态，空结果提供清晰反馈。

模块图按真实模块与交接关系生成。嵌入时统一容器、标题和文字尺寸，保留独立打开入口，完整图示支持缩放。详情集中展示需求、规则、依据、修订和关联成果。较长内容通过页内按钮切换，图示中的重复标题与重复详情由嵌入容器收敛。

需求列表使用表格与单项详情。选中行、模块和需求同时保持可识别状态。切换视图后保留键盘焦点，按钮与来源链接支持键盘操作。


## 点选阅读 v0.4

- 内容区以 16px 间距组织，关联成果使用紧凑按钮。需求详情使用需求、依据、修订三个按钮切换。
- 素材库优先呈现列表、媒体和原话，导入与处理记录通过页内按钮进入。
- 文档采用章节目录与单条内容选择，原型提供页面选择和设备预览。生成表单与检查记录通过生成入口查看。
- 状态和依据筛选使用可见选项按钮，由筛选入口显示。业务内容使用直接切换，避免多层折叠栏。
- Schema Canvas 沿用当前工作台配色、可读字号和紧凑嵌入模式，完整页面保留模型来源信息。


## 总览与素材阅读 v0.5

总览以项目目标和核心流程、成果入口、三项关键疑问组织信息。角色与范围横向换行展示，详细行动项与会议陈述随文档和来源保留。疑问优先展示需人判断的业务问题。

会议素材有重点时先显示重点，逐字稿每页 30 段。时间入口跨页定位原话，来源记录与原件完整保留。未导入本地录音时提供有效的飞书妙记入口，播放状态按实际媒体显示。


## 需求阅读 v0.6

功能需求采用模块图、模块选择、宽版详情的纵向结构。详情中以需求名称为主标题、稳定编号为辅助信息，左侧选择需求，右侧集中阅读一条。默认呈现功能内容、验收标准和具体疑问。规则、会议原话、修改与模块关联内容按任务切换。

选择图中节点、模块或需求行后，将所选详情带入视野。搜索、筛选、选中状态与来源关系保持一致，窄屏将需求选择与正文纵向排列。
