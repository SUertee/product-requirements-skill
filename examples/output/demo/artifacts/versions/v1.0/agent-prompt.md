## 强制执行原则

1. 先读取现有仓库的 AGENTS.md、README、架构与开发规范，保留已有成果，不为套模板重写项目。
2. 先建立 REQ ID → 现有模块 → 修改文件 → 测试用例的映射；REQ ID 必须稳定写入实现和测试。
3. TBD、未确认指标、预算、日期、接口字段和业务规则不得编造。非关键默认值写入实施记录，关键阻塞项集中询问。
4. 外部接口未接通时使用清晰的 Adapter/Mock 边界并标注模拟状态；不得把 Mock 说成真实联调成功，不得硬编码密钥。
5. 优先完成一条可操作的端到端主流程，再扩展相邻能力；允许局部完成，不因为单个可选字段缺失丢弃全部成果。
6. 每个模块完成后运行相关测试；最终执行单元、集成和主流程验证。未执行的检查必须明确写未验证。
7. 保留人工锁定内容，不覆盖他人已有修改。任何实现与需求冲突时，回到 Evidence 和验收标准核对。

## 需求、验收与原话证据

### REQ-001 · 客户数据权限

- 状态：confirmed；证据等级：E1；版本：v1.0
- 描述：管理员查看全部客户，普通销售仅查看本人负责的客户。
- 角色：管理员、普通销售
- 业务场景：销售或管理员打开客户列表
- 触发：用户进入客户列表或客户详情
- 目标结果：不同角色只看到其权限范围内的客户和跟进记录。
- 范围：客户列表权限过滤；客户详情权限过滤
- 约束：沿用现有 CRM 客户负责人口径
- 依赖：现有 CRM 用户角色与客户负责人数据
- 人工锁定：整条=True；字段=无

验收标准：

1. 管理员打开客户列表时可查看全部客户。
2. 普通销售只能查看本人负责的客户，不能通过详情地址查看他人客户。

原话证据：
- [EVD-9c7fd82cc29bc1324ae9 / E1] 管理员可以查看全部客户，普通销售只能查看本人负责的客户。
- [EVD-af3889ad59b1985f8178 / E0] 历史草案：所有角色均可查看全部客户和跟进记录。
- [EVD-5bbc1e4806d5c0ee831a / E1] 第一版沿用现有 CRM 数据，销售在电脑浏览器使用，不接入外部短信服务。

### REQ-002 · 客户名称查询

- 状态：confirmed；证据等级：E1；版本：v1.0
- 描述：客户列表支持输入客户名称并显示匹配客户。
- 角色：普通销售、管理员
- 业务场景：用户在客户列表查找目标客户
- 触发：用户在客户列表输入客户名称并查询
- 目标结果：列表显示权限范围内名称匹配的客户。
- 范围：客户名称查询；匹配结果列表
- 约束：仅查询当前用户权限范围内的客户
- 依赖：现有 CRM 客户数据
- 人工锁定：整条=False；字段=constraints

验收标准：

1. 输入存在的客户名称后显示匹配客户。
2. 查询结果不包含当前用户无权查看的客户。

待确认：
- 未明确名称查询是精确匹配还是模糊匹配。

原话证据：
- [EVD-bbc744525a0d0fffe8c4 / E1] 客户列表需要支持按客户名称查询，输入名称后显示匹配客户。
