# 内置 UI 规范 · 历史记录

2026-11-23 从 Skill 包的 ui-design.md 移出。以下是 v0.2—v0.6 工作台视觉调整的记录，现行规定以 [内置 UI 规范](../../product-requirements/references/ui-design.md) 与 [工作台页面规范](../../product-requirements/references/workbench.md) 为准。

## 当前工作台生成资产

assets/workbench-template.html 定义七页的应用外壳，assets/workbench.css 复用 ParTrace Vision workbench 的样式基础，assets/workbench.js 组织项目数据与页面交互。侧栏名称使用总览、会议素材、功能需求、方案文档、原型预览、技术设计、评审记录。


## 工作台视觉收敛

v0.2 统一使用单套工作台样式。深蓝灰侧栏、浅灰页面与白色内容区承载七个简短入口。内容区按 20px 节奏分组，常规卡片 24px 内边距，层级通过字号、间距和边框表达。

总览优先展示目标、范围和具体疑问，需求数量使用紧凑统计行，八要素画像在文档中按章节阅读。模块内的需求采用分隔线组织，减少嵌套卡片边框。文档以正文层级阅读，实体字段使用表格，结构化内容使用列表与定义项。

辅助文案只提供独立信息。运行／评审状态使用文字，页面空态说明具体缺失内容。移动端导航横向排列，表格局部滚动。


## 功能需求样板 v0.3

功能需求使用紧凑工具栏、模块选择条、主内容区和按选择更新的详情区。桌面并排展示，窄屏改为纵向阅读。模块图与列表共用筛选和选中状态，空结果提供清晰反馈。

模块图按真实模块与交接关系生成。嵌入时统一容器、标题和文字尺寸，保留独立打开入口，完整图示支持缩放。详情集中展示需求、规则、依据、修订和关联成果。较长内容通过页内按钮切换，图示中的重复标题与重复详情由嵌入容器收敛。

需求列表使用表格与单项详情。选中行、模块和需求同时保持可识别状态。切换视图后保留键盘焦点，按钮与来源链接支持键盘操作。


## 点选阅读 v0.4

- 内容区以 16px 间距组织，关联成果使用紧凑按钮。需求详情使用需求、依据、修订三个按钮切换。
- 素材库优先呈现列表、媒体和原话，导入与处理记录通过页内按钮进入。
- 文档采用章节目录与单条内容选择，原型提供页面选择和设备预览。生成表单与检查记录通过生成入口查看。
- 状态和依据筛选使用可见选项按钮，由筛选入口显示。业务内容使用直接切换，避免多层折叠栏。
- Schema Canvas 沿用当前工作台配色、可读字号和紧凑嵌入模式，完整页面保留模型来源信息。


## 总览与素材阅读 v0.5

总览以项目目标和核心流程、成果入口、三项关键疑问组织信息。角色与范围横向换行展示，详细行动项与会议陈述随文档和来源保留。疑问优先展示需人判断的业务问题。

会议素材有重点时先显示重点，逐字稿每页 30 段。时间入口跨页定位原话，来源记录与原件完整保留。未导入本地录音时提供有效的飞书妙记入口，播放状态按实际媒体显示。


## 需求阅读 v0.6

功能需求采用模块图、模块选择、宽版详情的纵向结构。详情中以需求名称为主标题、稳定编号为辅助信息，左侧选择需求，右侧集中阅读一条。默认呈现功能内容、验收标准和具体疑问。规则、会议原话、修改与模块关联内容按任务切换。

选择图中节点、模块或需求行后，将所选详情带入视野。搜索、筛选、选中状态与来源关系保持一致，窄屏将需求选择与正文纵向排列。
