# 开发流程

围绕一次真实会议完成输入、需求核对、成果生成与反馈。模块职责见 [模块拆分](../architecture/modules.md)，数据约定见 [数据契约](../architecture/contracts.md)。本轮功能开发使用 feat/workflow-execution，基线来自 dev/workbench-foundation。

可执行功能、异常处理、开发顺序、测试和验收见 [功能开发 Spec](functional-spec.md)。

## 用户流程

1. 打开项目工作台，在会议素材中导入录音、录屏、逐字稿，或选择飞书妙记链接。
2. 接收器保存原件、去重并记录来源。文本标准化，录屏提取音轨，有可用逐字稿后进入需求分析。
3. 主 Skill 读取来源片段、客户背景和原基线，提取八要素、REQ、疑问与冲突，再建立业务模型。
4. 工作台中核对模块、原话和验收标准。缺失内容集中记录，人工补充建立新来源。
5. 生成项目方案与 PRD，负责人确认范围、规则和验收。
6. 生成交互原型、流程架构与 ERD，汇入同一版本工作台。
7. 核对核心流程、模拟接口和客户可见内容，按授权部署原型。反馈形成需求差异和下一版本。

接入选用两条通道。本地文件支持先完成确定性的预处理；飞书妙记已有逐字稿时直接保留其文本，原始音视频用于对照或 ASR 测试。录屏当前处理音轨，画面中的 UI 和操作事件提取另行开发。

## 妙记驱动的接入流程

2026-11-17 用户确认采用以下目标流程。

**会议云录制／上传音视频 → 妙记处理完成 → Connector 获取逐字稿和原件 → Skill 分析需求 → 生成内部工作台 → 人工确认 → 生成并分享客户原型。**

### 素材进入方式

- 飞书会议在会中开启云录制，或提前配置自动录制，会后生成妙记。录制内容包含会议音频、参会人视频和共享内容画面。[官方录制说明](https://www.feishu.cn/hc/zh-CN/articles/360043230014-使用录制功能)
- 已有录音、录屏和其他音视频可上传妙记进行转写。录音豆导出的文件也可尝试此入口，具体格式和导出方式按实际设备验证。[官方上传说明](https://www.feishu.cn/hc/zh-CN/articles/318505042260-飞书智能伙伴使用说明书)
- 本地文件导入继续作为工作台入口，按项目需要选择妙记转写或其他已授权 ASR 服务。

### Connector 到工作台

1. 确认目标妙记及项目归属，等待文字记录与所需录制可获取。
2. 获取带时间定位的逐字稿，按需获取原始音视频，保留妙记标识、读取身份与来源。
3. 标准化为 sources.jsonl，结合客户背景、历史材料和已有需求基线执行分析。
4. 整理业务模块、REQ、原话依据、八要素、疑问与模型，生成方案、PRD 和内部工作台草稿。
5. 人工核对范围、规则和验收后生成交互原型，复核后按授权分享给客户，反馈进入下一版本。

### 自动触发的开发边界

当前已实现指定妙记链接获取、文件接收、来源标准化、目录监听和显式查询的妙记就绪轮询。ASR 与主 Skill 通过启动时配置的命令适配器接入，实际比赛宿主调用与平台事件订阅继续联调。

自动链路以“所需妙记产物已就绪”为处理条件。优先验证平台可用事件，必要时评估轮询方式。事件到达后核对资源权限与项目归属，以材料及处理版本去重。文字记录或媒体尚未就绪时记录等待状态，获取失败保留原因与重试入口。详细平台依据见 [华为与飞书接入核查](../references/huawei-feishu.md)。

| 顺序 | 工作范围 | 完成条件 | 当前实现 |
| --- | --- | --- | --- |
| 1 | 导入、接收箱与来源 | 原件可查、同项目同输入去重、字幕定位、失败保留、重试留历史 | 本地文件接收、文本标准化、ffmpeg 音轨提取与接收箱已实现 |
| 2 | 飞书 Connector | 指定妙记可获取文本和媒体，保留身份、token 与来源，权限失败可识别 | CLI 适配器和页面入口已实现，四项读取／导出权限已验证生效，真实样本逐字稿与分析已完成，原媒体下载被 CLI 地址校验拒绝 |
| 3 | 需求分析编排 | sources → project.json，结构与引用校验通过，事实／推断和未知可查 | 已有任务快照、结果校验与命令适配器，真实码道调用待验证 |
| 4 | 模块定义与评审 | 原话双向回查、状态筛选、版本绑定的意见、人工锁定保护 | 已实现浏览、修订、锁定和意见应用到新版本 |
| 5 | 文档与技术设计 | 单篇阅读、章节清晰、同版本来源与实体／接口可查 | 文档、业务流程图和 ERD 已生成合成样例，真实业务模型质量待评审 |
| 6 | 交互原型 | 选定核心任务可完成，异常和返回路径可操作，页面关联 REQ | 已确认页面规格可生成表单／列表原型，浏览器主流程通过 |
| 7 | 分享与增量 | 客户只获取选定文件，反馈可定位旧版与影响范围 | 已实现选定原型的发布包与反馈版本，公网部署待完成 |
| 8 | 比赛宿主联调 | 在码道或果办中完成同一条样例链路，核对依赖与许可 | 官方飞书接入可查，当前机器上的比赛宿主运行未验证 |

## 分析与生成的执行方式

本地运行器处理接收、预处理和评审存储。语义需求分析由主 Skill 所在宿主执行，读取接收箱的 sources.jsonl 与 analysis-request.md，再结合前情和已有基线整理 project.json。结构化输入通过 build_documents.py 校验与生成新目录。

接收完成、来源可读、语义分析完成、人工确认和客户发布各自记录。本地运行器通过分析请求和命令协议完成交接，并持久保存执行状态。常驻目录接收与妙记轮询已实现，比赛宿主的实际自动调用方式待验证。运行命令见 [运行流程](../../product-requirements/references/execution.md)。

## 测试流程

- 合成文本与字幕验证来源 ID、定位、中文编码、空输入、坏字幕与重复输入。
- 合成带音轨视频验证 ffmpeg 输出 16kHz 单声道 WAV，原视频保留。无音轨、依赖缺失和失败重试分别检查。
- 选定一份已授权妙记，先取逐字稿，再取原始音视频，记录实际格式、权限、时间定位与来源。
- 将同一文本分别人工整理与 Skill 整理，核对遗漏、无依据新增、规则冲突和验收完整度。
- 检查模块与原话双向定位、文档阅读、技术标签、预览入口、评审刷新与保存冲突。
- 在真实浏览器核对桌面与窄屏、键盘、媒体播放和控制台。代码级测试记录与视觉结论分别维护。
