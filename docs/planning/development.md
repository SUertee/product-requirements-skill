# 开发流程

围绕一次真实会议完成输入、需求核对、成果生成与反馈。模块职责见 [模块拆分](../architecture/modules.md)，数据约定见 [数据契约](../architecture/contracts.md)。开发沿用 dev/workbench-foundation。

## 用户流程

1. 打开项目工作台，在会议素材中导入录音、录屏、逐字稿，或选择飞书妙记链接。
2. 接收器保存原件、去重并记录来源。文本标准化，录屏提取音轨，有可用逐字稿后进入需求分析。
3. 主 Skill 读取来源片段、客户背景和原基线，提取八要素、REQ、疑问与冲突，再建立业务模型。
4. 工作台中核对模块、原话和验收标准。缺失内容集中记录，人工补充建立新来源。
5. 生成项目方案与 PRD，负责人确认范围、规则和验收。
6. 生成交互原型、流程架构与 ERD，汇入同一版本工作台。
7. 核对核心流程、模拟接口和客户可见内容，按授权部署原型。反馈形成需求差异和下一版本。

接入选用两条通道。本地文件支持先完成确定性的预处理；飞书妙记已有逐字稿时直接保留其文本，原始音视频用于对照或 ASR 测试。录屏当前处理音轨，画面中的 UI 和操作事件提取另行开发。

## 实施顺序

| 顺序 | 工作范围 | 完成条件 | 当前实现 |
| --- | --- | --- | --- |
| 1 | 导入、接收箱与来源 | 原件可查、同项目同输入去重、字幕定位、失败保留、重试留历史 | 本地文件接收、文本标准化、ffmpeg 音轨提取与接收箱已实现 |
| 2 | 飞书 Connector | 指定妙记可获取文本和媒体，保留身份、token 与来源，权限失败可识别 | CLI 适配器和页面入口已实现，真实账号缺 scope，样本测试待完成 |
| 3 | 需求分析编排 | sources → project.json，结构与引用校验通过，事实／推断和未知可查 | 主 Skill 执行规则已具备，常驻后台自动调用待接入 |
| 4 | 模块定义与评审 | 原话双向回查、状态筛选、版本绑定的意见、人工锁定保护 | 浏览、筛选和评审意见保存／导出已实现；意见应用到新版本待实现 |
| 5 | 文档与技术设计 | 单篇阅读、章节清晰、同版本来源与实体／接口可查 | 文档生成和结构化阅读已实现，图示／ERD 输入适配待接入 |
| 6 | 交互原型 | 选定核心任务可完成，异常和返回路径可操作，页面关联 REQ | 预览容器和页面定义已实现，按 PRD 自动生成原型待实现 |
| 7 | 分享与增量 | 客户只获取选定文件，反馈可定位旧版与影响范围 | 规范已定义，发布执行与增量应用待实现 |
| 8 | 比赛宿主联调 | 在码道或果办中完成同一条样例链路，核对依赖与许可 | 官方飞书接入可查，当前机器上的比赛宿主运行未验证 |

| 方案文档 | 方案／PRD 切换、结构化内容阅读、原文件入口 | 文档章节定位、增量对照与正式确认 |
| 原型预览 | 实际文件预览、独立打开、页面定义与关联 REQ | 页面生成、设备预览、任务演练、客户发布 |

## 分析与生成的执行方式

本地运行器处理接收、预处理和评审存储。语义需求分析由主 Skill 所在宿主执行，读取接收箱的 sources.jsonl 与 analysis-request.md，再结合前情和已有基线整理 project.json。结构化输入通过 build_documents.py 校验与生成新目录。

接收完成、来源可读、语义分析完成、人工确认和客户发布各自记录。本地运行器当前通过分析请求文件完成交接，常驻自动执行需要在比赛宿主中验证任务调用方式，再实现队列调度。

## 测试流程

- 合成文本与字幕验证来源 ID、定位、中文编码、空输入、坏字幕与重复输入。
- 合成带音轨视频验证 ffmpeg 输出 16kHz 单声道 WAV，原视频保留。无音轨、依赖缺失和失败重试分别检查。
- 选定一份已授权妙记，先取逐字稿，再取原始音视频，记录实际格式、权限、时间定位与来源。
- 将同一文本分别人工整理与 Skill 整理，核对遗漏、无依据新增、规则冲突和验收完整度。
- 检查模块与原话双向定位、文档阅读、技术标签、预览入口、评审刷新与保存冲突。
- 在真实浏览器核对桌面与窄屏、键盘、媒体播放和控制台。代码级测试记录与视觉结论分别维护。
