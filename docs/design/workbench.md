# 工作台与原型设计

界面规则的权威入口为 [内置 UI 规范](../../product-requirements/references/ui-design.md)，基础样式为 [ui.css](../../product-requirements/assets/ui.css)。本页定义当前产品的页面组织与复核入口。

## 内部工作台

| 页面 | 直接展示的内容与操作 |
| --- | --- |
| 总览 | 项目目标、范围、版本、已生成成果与具体待确认问题 |
| 会议与素材 | 会议记录、逐字稿、可随包携带的音频／文档、前情资料与原话定位 |
| 功能模块与需求 | 客户业务模块、关联 REQ 卡、证据类别、确认状态与原话回查 |
| 方案与 PRD | 可读文档、需求引用、开放问题和定义评审决定 |
| 业务模型 | Schema Canvas ERD、模型来源与确认状态 |
| 流程与架构 | Archify 图示及对应需求版本 |
| 交互原型 | 核心任务预览、页面状态、对应确认版本与模拟能力说明 |
| 评审与变更 | 旧值、新值、来源、影响、决定及发布选择 |

导航随实际产物启用。卡片优先显示真实问题、记录、内容和操作，标题下重复说明按内置规则精简。长背景按需展开，必要的错误、数据状态和操作约束就近显示。

## 客户原型

方案／PRD 确认后按产品类型、核心任务和目标设备形成页面规范。结合客户已有样式与必要的产品参考，用内置 UI 规范生成一条可操作主流程，覆盖相关空态与错误分支。负责人复核后选定客户可见版本。

## 参考副本的使用

ParTrace Vision 的 [workbench](../references/partrace-workbench/workbench.html)提供侧栏、内容区、预览布局与视觉参考，副本保留原示例业务内容。设计迭代可先修改该副本，再将适用模式整理到当前 UI 规范与模板中。

工作台生成与客户页面生成分别消费同一项目数据，最终输出按 [产物合同](../../product-requirements/references/output-contract.md)关联版本。
