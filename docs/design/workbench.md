# 工作台页面设计分析

2026-11-17 用户确认的页面框架，首版实现按该结构推进。分析依据为 ParTrace Vision 的 workbench 副本和组员提供的产品需求工作台 HTML。本次检查静态结构与脚本，尚未执行浏览器视觉与交互验证。

## 设计原则

2026-11-19 用户明确设计的第一原则为 **简洁清晰**，整体设计保持克制。页面评审依据 [内置 UI 规范](../../product-requirements/references/ui-design.md) 的内容、层级、交互和视觉取舍标准，核对必要信息是否易读、操作是否直接、完整依据是否可查。

## 两份参考的采用方式

| 参考 | 已观察到的优点 | 本项目的采用建议 |
| --- | --- | --- |
| ParTrace Vision workbench | 侧栏切页；原型预览、源码查看与下载；功能模块选择；数据库与 API 页面；流程和架构嵌入 | 以其页面框架、内容区、预览与视觉语言为基础，适配客户项目数据 |
| 组员需求工作台 | 八要素画像；会议原话与 REQ 关联；证据等级和需求状态分开；搜索筛选；疑问清单；项目 JSON 导出 | 加强需求定义、来源回查和评审问题组织 |

ParTrace Vision 原页面保留原项目的业务、任务及展示素材，组员页面含具体客户场景。通用工作台采用其结构与模式，项目内容由当前会议及前情资料形成。参考副本与来源见 [参考索引](../references/README.md)。

## 工作台要完成的任务

- FDE／PM 核对客户是谁、谈了什么、每项需求依据是什么，以及还有哪些疑问。
- 内部成员从功能模块理解范围与业务规则，查看方案、PRD、模型、接口与原型。
- 负责人确认定义、复核生成成果，再选择面向客户的原型版本。
- 后续会议或客户反馈进入对应需求，展示变化与影响，形成下一轮版本。

工作台由同一项目数据组织页面，证据、需求、模块、文档和原型保持可追溯关系。

## 建议的信息架构

采用以下七个一级页面。技术设计通过页内标签提供流程／架构、数据库和 API，保留 ParTrace Vision 的完整展示能力。

| 页面 | 核心内容 | 主要操作 |
| --- | --- | --- |
| 总览 | 客户与场景、目标、范围、版本、已生成成果、关键待确认项 | 进入对应材料、模块、原型或评审 |
| 会议素材 | 会议列表、音频、逐字稿、附件、客户背景与历史资料、来源定位 | 播放或预览、查看关联需求、核对前情 |
| 功能需求 | 业务模块、模块中的 REQ、规则、异常、验收、依据与疑问 | 核对需求、查看原话、标明确认或暂缓 |
| 方案文档 | 对应版本的文档、引用、范围与开放问题 | 阅读、下载、定位相关需求、确认定义 |
| 原型预览 | 由已确认定义生成的页面、核心任务、版本和模拟能力说明 | 操作、切换页面、定位对应需求、提交反馈 |
| 技术设计 | 流程／架构图、业务数据模型、字段、关系、接口草案及来源 | 打开图示、选实体或接口、回查需求 |
| 评审记录 | 按影响组织的问题、决定、变更旧值／新值、影响和发布版本 | 确认或暂缓具体事项、查看差异、选择客户可见内容 |

开发流程可按实际项目需要放入技术设计的说明中。路演素材在有对应交付需求时作为项目资料入口出现。本版沿用七个一级入口。

## 会议与素材页

建议采用材料列表加阅读／播放区，材料选择后展示其实际内容。

### 材料层次

- 会议记录包含会议名称、已有日期、原始音频和逐字稿，时间不明确时保留未知。
- 前情资料包括客户背景、历史项目、已有系统、旧方案和需求基线，记录版本与关联状态。
- 补充材料包括客户文档、表格、图片、链接和人工说明，保留来源信息。

### 需求回查

从某条 REQ 点击依据后，定位到原材料及对应时间或段落。原话处展示引用它的需求，形成双向查看入口。有转写时间时讨论播放定位，没有时间时使用原文段落。

上传、导入、转写和失败状态就近显示。阶段处理完成只代表材料可读，分析质量与需求确认通过另外的状态记录。

## 功能模块与需求页

这里的模块表示客户项目的业务能力，例如客户管理、工单处理或报表。模块下组织多条需求，REQ ID 保持独立和稳定。

| 层次 | 保存什么 | 页面表达 |
| --- | --- | --- |
| 功能模块 | 名称、业务目标、范围、关联 REQ | 模块导航或模块区域，展示实际需求 |
| 需求卡 | 角色、触发、行为、输入输出、规则、异常、验收与状态 | 直接展示行为、验收和需要确认的问题 |
| 来源依据 | 原话、段落／时间、材料及版本、证据类型 | 卡片引用入口，展开原话或跳转材料 |
| 待确认项 | 缺失或冲突内容、影响范围、决定 | 显示具体问题与相关需求 |

“定义需求”可以放在这个页面完成。早期尚未明确模块归属的 REQ 可先集中查看，业务关系清楚后再归集。一个需求影响多个模块时保留关联，避免复制出多条独立需求。

需求状态和证据类型分别展示。客户明确提出的需求也需要核对范围与验收，模型建议需要保留其依据与建议标识。候选交互包括搜索、按模块／状态／证据筛选、原话回查及人工核对。

## 原型与技术页面

原型沿用 workbench 的预览区、页面切换和独立打开方式。根据客户产品的任务与设备调整预览尺寸，标明对应需求版本、示例数据及真实接口情况。

技术设计复用已有页面的内容展示方式。Archify 承担流程与架构图，Schema Canvas 承担实体、字段和关系探索，API 草案关联业务模块与 REQ。图示与接口设计的生成和实际接通分别记录。

## 总览与评审

总览首屏显示项目目标、范围、成果入口与需要决定的问题。画像八要素在方案文档中按章节阅读。卡片通过实际内容、状态和操作表达用途，辅助文字只保留帮助判断与操作的独立信息。

评审按需求范围、业务规则、数据模型、页面行为和发布范围归集问题。问题注明影响的需求与产物。未解决问题保留影响范围，负责人可决定暂缓相关内容并确认其他已明确部分。

人工确认分为定义确认和最终成果复核。前者确定方案／PRD 的核心范围、规则与验收，后者核对原型和工作台并选择客户可见版本。

## 页面内容与生成资源

有效页面规范维护在 [包内工作台规范](../../product-requirements/references/workbench.md)，覆盖七页任务、常驻字段、展开内容、来源回查和缺失状态。

- 会议素材采用材料列表与原话阅读区，会议信息随选中材料显示。
- 功能需求采用模块列表与需求详情，搜索和双维度筛选共同作用。
- 方案文档顶部切换方案和 PRD，左侧选择章节，右侧阅读当前内容。
- 总览提供真实成果入口，技术设计保留三类标签，评审展示问题和已有决定。

模板、样式与交互脚本位于包内 assets。开发原始参考继续保存在 docs/references/partrace-workbench，运行产物进入 runs 下的版本目录。独立安装 Skill 包即可使用生成资源。

本轮已实现上述列表与详情布局。本地运行器进一步支持素材导入、指定妙记 Connector、接收箱和版本绑定评审保存，入口见 [输入与本地工作台](../features/intake.md)。ASR、后台自动分析、原型自动生成和评审应用继续开发。代码、DOM 与 HTTP 测试已执行，浏览器观感仍待核对。

## 视觉基线 v0.2

采用统一的深蓝灰侧栏、浅灰页面与白色内容区，七页导航使用简短名称。总览将计数收敛为一行，画像进入文档章节，模块内需求通过分隔线组织。文档使用标题、正文和列表排版，模型字段使用表格。具体间距、颜色和组件约定统一见包内 UI 规范。


## 功能需求样板 v0.3

2026-11-17 按用户确认的方向实现功能需求页，采用模块图／列表切换、模块选择条、主内容与单项详情。桌面并排，窄屏纵向；搜索同时匹配需求、所属模块及关联原话。模块图由 Archify 实际生成，采用显式 module_relations，点击节点关联对应需求。

本轮在开发时使用 Taste Skill 2.5.1 的统一系统原则与浏览器审视方法，延续用户指定的 ParTrace workbench 视觉。有效页面规则写入项目现有 references，组件写入 assets。开发工具与项目包依赖按用户确定的采用范围维护。

模块详情汇总关联页面、实体、API 与交接关系，再显示当前需求的行为、验收、依据与修订操作。现有生成状态、评审和版本流程继续使用同一项目数据。后续技术页的目标为架构、数据、时序、API 四个标签，当前技术页仍保留已有三个标签。


## 点选阅读 v0.4

2026-11-17 根据页面反馈移除工作台内容折叠栏。关联成果改为直接入口，需求使用需求／依据／修订切换，状态和证据通过筛选面板选择。素材页默认进入素材库，导入和处理记录分别点选进入。

方案书补充摘要、背景、目标范围、解决方案、实施资源和验收风险结构。PRD 保留已有规范与两个模板链接，结构化字段转换为可读列表。文档选择章节后显示对应正文，多条需求或原始依据进一步点选单条。未提供的里程碑、资源和成功指标标记待确认。

数据库页以实际 Schema Canvas ERD 为主体，选择实体查看字段与关系。原型页采用 ParTrace workbench 的页面选择、设备预览与独立打开组织方式，页面定义和生成操作通过单独入口进入。


## 总览与会议素材 v0.5

2026-11-19 使用真实小组妙记逐字稿进行页面验证。总览收敛为项目定义、成果入口和关键疑问，定义中展示已有核心流程；角色和范围横向排列。会议素材优先展示有原话支持的重点，每个时间入口进入对应逐字稿页，每页最多 30 段。原话保留说话人，未识别的发言标签沿用来源。

## 面向首次阅读者的表达

2026-11-19 用户进一步确认通过功能、实际板块和可视化表达内容，功能卡片和 footer 的介绍性 description 移除。工作台用于 PM／FDE 回看、推进与分享，首次阅读者也应看懂项目目标、各页内容和下一步操作。有效标准统一在内置 UI 规范维护。

总览新增基于实际状态的下一步入口。来源入口显示原话的时间或段落；模块详情直接进入需求内容，重复介绍和页尾流程说明移除。原型空态提供导入、核对或生成入口，技术标签使用数据模型和接口等业务名称。


## 功能需求阅读层级

2026-11-19 对照 ParTrace Vision 实际开发模块页的模块图、模块选择和内容区，调整本项目功能需求页为上方图示、下方宽版详情。详情以需求名称作为标题，REQ 标识作为“需求编号”辅助显示；默认阅读功能、验收和待确认问题。规则、会议原话、修改与关联内容分别进入，避免窄侧栏同时承载多层信息。

原话、规则、字段修订与内部标识继续从同一项目数据读取。具体布局与交互以包内页面规范和 assets 为准。

## 会议内搜索与文档编辑

2026-11-19 搜索移到选中会议的右侧阅读区，仅查询该会议逐字稿。左侧会议列表保持可见，换会议清空关键词。

方案和 PRD 按章节编辑、点选预览，保存生成新版本并打开该文档。打印输出整份当前正文，使用浏览器打印窗口另存为 PDF，下载正文输出 Markdown。人工正文与结构化需求分别保存，自动分析保留人工正文。未保存草稿仅存在当前页面，刷新前应保存或下载。

2026-11-19 移除各页标题下的“内部评审草稿 · 版本 · 待确认总数”，标题直接衔接当前内容。真实评审数据继续在评审页与具体需求中查看。

## 成果直接浏览

2026-11-19 技术设计移除设计／生成模式，直接展示三个内容标签。原型预览移除预览／页面定义／生成模式，直接提供实际页面与设备切换；缺少成果时显示“暂无原型”。生成由 Skill 执行流程负责，工作台用于浏览与评审。总览缺少原型且需求已核对时进入项目方案。

## 总览与评审阅读组织

2026-11-19 总览明确项目用途、当前版本和接下来三类信息。项目一句话优先使用 summary，缺省读取目标；阶段根据实际需求确认和原型文件判断，不虚构实施进度。成果入口集中在当前版本，待解决问题与操作集中在接下来。

评审页以业务需求名称组织选择列表，同一需求的重复问题合并，详情下直接填写意见。待确认、已记录、版本变更、交付分开呈现，保存意见绑定所选对象，避免长页同时堆放问题、表单、差异和发布操作。

## 素材职责、模板与 HTML 修订

2026-11-19 会议素材分为三项，各入口只承担对应任务。

| 入口 | 用途 |
| --- | --- |
| 素材 | 阅读重点、查看原话、核对需求依据 |
| 导入 | 接收文件、妙记和前情资料 |
| 处理流程 | 查看接收→转写→需求分析→工作台，定位失败和打开成果 |

处理阶段依据真实 job 与分析任务展示，关联录音和逐字稿按 job 关系匹配。没有执行的阶段显示未开始，不以进度动画冒充处理。最近分析记录保留实际操作入口，隐藏任务 ID 和无关的文档／图示任务。

技术页的模块图移回功能需求职责，流程架构只展示一张流程图。Schema Canvas 嵌入页报告实际内容高度，实体详情变化后重算，工作台校验消息来源窗口并限制高度，减少外层空白。接口没有结构化定义时保留空态，不编造已实现 API。

方案与 PRD 分别有独立模板并参与实际生成。HTML 作为呈现结果，方案／PRD 的章节正文修改保存为新版本，已有人工正文受保护。原型修改仍通过需求、页面定义和 Skill 再生成；当前没有任意 HTML 可视化拖拽编辑器。外部部署分享范围仍由交付复核决定。
