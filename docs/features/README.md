## 验证方式

- Python 回归覆盖输入、版本、引用、并发、锁定、评审、生成、发布包和后台接入。
- [DOM 回归](../../tests/check_workbench.cjs) 覆盖七页、分析状态、人工解锁、评审请求、生成错误、键盘标签，以及原型校验／创建／搜索。
- 合成端到端使用 [固定会议输入](../../tests/fixtures/customer-meeting.txt) 与明确的宿主响应夹具，覆盖生成到反馈。该夹具验证流程协议，语义分析质量另以真实素材核对。
- 浏览器与真实样本的环境、操作和缺口见 [工程进度](../progress/implementation.md)。真实客户素材保留在已忽略的本地 runs 目录。

## 运行入口

从仓库根目录运行。

```bash
python3 -m unittest discover -s tests -q
node --check product-requirements/assets/workbench.js
python3 product-requirements/scripts/workflow.py --help
python3 product-requirements/scripts/intake_runner.py --help
```

DOM 回归需可解析的 jsdom 模块，使用外部环境安装的 jsdom 或 NODE_PATH 指向已有依赖，传入含 workbench 与 prototype 的合成版本目录。

```bash
node tests/check_workbench.cjs /path/to/synthetic/version
```

素材导入、Connector 和本地服务的详细参数见 [输入与本地工作台](intake.md)。Skill 入口、外部依赖位置和许可证见工程 README。


### 工作台点选阅读

会议素材提供素材库、导入和处理记录切换；需求详情提供需求、依据和修订切换，关联成果直接打开目标页面。方案和 PRD 支持章节点选与单条需求／依据阅读。数据库优先嵌入实际生成的 Schema Canvas，原型预览提供页面与设备选择。2026-11-17 使用合成会议完成本地生成和浏览器检查，详见工程进度记录。


### 真实会议阅读

总览展示项目目标、已有核心流程、成果和三项关键疑问。会议素材支持有来源的重点、完整逐字稿分页及跨页回查。会议重点引用核对所属材料，真实逐字稿在本地运行目录保留。2026-11-19 以一场 46 分 11 秒的妙记验证 549 段原话、四条重点和对应页面，记录见工程进度。


### 功能需求的名称与详情

模块图／列表与下方详情按纵向组织。模块内按业务名称选择需求，编号作为辅助信息；默认展示功能与验收，规则、会议原话、修改和模块相关内容可分别查看。选择模块、节点或需求行会显示对应详情。搜索、筛选、原话回查及评审字段标识沿用当前项目数据。

## 章节编辑与会议内搜索

会议搜索位于右侧阅读区，仅查当前会议。方案／PRD 支持章节编辑、预览、Markdown 下载及整份正文打印；PDF 通过浏览器打印窗口另存。连接本地服务时可保存为新版本，保留旧版和人工来源，基线变化时拒绝覆盖。后续分析保留人工正文。正文编辑不会直接同步结构化需求字段。

88 项 Python 回归及 DOM 检查覆盖保存、幂等重试、基线冲突、非法文件名、保留图示、人工正文保护、会议搜索范围、保存失败保留草稿与整份打印内容。浏览器已用合成 PRD 验证保存并打开 v3，回读修改；真实会议已验证本地搜索。打印入口已调用，系统 PDF 保存尚未实测。

技术设计与原型预览直接展示已有成果，移除设计／生成模式和生成表单；原型保留页面、设备切换与独立打开，暂无成果时显示简洁空态。生成仍由 Skill 后台流程执行。

总览展示项目用途、当前版本／阶段、成果与下一步；评审页按需求点选问题，历史意见、版本变更和交付分开查看。DOM 验证所选对象保存、记录回读、版本切换及原有修订请求。

会议处理流程按素材展示接收、转写、分析与工作台阶段。方案和 PRD 均使用包内独立模板。技术页仅显示一张流程图，模块图仍在功能需求；数据模型预览随内容高度调整。接口定义缺失时显示空态。HTML 原型当前通过需求／页面定义再生成修订，未实现任意 HTML 可视化编辑器。

功能需求提供功能模块、UML 用例图、需求列表三种阅读方式；用例图从已有角色与需求构建，点选功能联动需求详情。技术设计使用独立技术架构数据，以内容高度展示系统层次和组件，不再重复业务流程或模块图。缺少架构数据时保留待确认空态，设计建议与已确认架构分别标记。
