# 产品定义

产品需求落地 Skill 面向 PM／FDE，将客户会议录音、逐字稿和前情资料整理为带依据的需求，完成建模后生成方案和 PRD，经人工确认再生成原型，汇总到工作台并组织复核与客户反馈。

## 设计理念

**第一原则是简洁清晰，设计保持克制。** 围绕用户理解项目、核对依据和完成操作组织内容，优先呈现必要信息，完整细节通过明确入口查看。内容、层级、交互与视觉的取舍标准统一维护在 [内置 UI 规范](../product-requirements/references/ui-design.md)。

## 任务与产出

- 输入来自文件、会议材料导出或已配置的硬件接入，保留原始定位。
- 后台可先处理已有材料，生成需求、疑问和文档框架，负责人回来后集中补全。
- 需求保留八要素画像、稳定 REQ ID、原话依据、冲突与人工确认。
- 内部查看方案、PRD、业务模型、流程与架构、原型和评审记录。
- 客户体验负责人选定的原型版本，反馈经核对形成下一轮修改。

## 首版范围

先以脱敏逐字稿验证需求到成果的完整链路，再接入 ASR 和 PC 后台任务。录音豆通过实际型号支持的方式接入，自动跨端传输需实测。界面由主 Skill 的内置样式规范生成，Archify 与自有 Schema Canvas 承担图示和数据模型展示。

内部团队分享浏览并汇总意见，负责人通过 Skill 修订。人工确认分别覆盖方案／PRD 和最终原型／发布范围。缺少依据的字段保留待确认。

## 验收方向

检查来源追溯、关键遗漏、无依据新增、需求与页面一致、人工锁定保护、失败恢复和对外内容范围。耗时包括生成、核对与纠错，成本包括人工、ASR、模型与实际托管投入。具体阈值以实际样本基线确定。

使用流程与字段规则见 [主 Skill](../product-requirements/SKILL.md)和[输出合同](../product-requirements/references/output-contract.md)。
